# wafflebar Architecture (v1 / M2)

wafflebar is a **desktop panel** (see `PRIOR_ART.md`), not a status line. This doc locks the
contracts M2 builds against. Scope of the first coding pass: the `Module` + `WindowManager`
frameworks and the three dwl modules (tags → window → taskbar); tray/launcher/notifications/
popups are *architected here, stubbed in code*.

## Layering

- **`wafflebar-core`** (GTK-free): config, grid engine, and now the **trait/contract layer** —
  `Module`, `View`, `Event`, `ActionId`, `WindowManager`. Kept GTK-free *on purpose* (see
  "v1→v2" below): everything that crosses a trait boundary must be serializable.
- **`wafflebar`** (bin, GTK4): the **host** — owns the GLib main loop, the GTK widget tree,
  layer-shell surfaces, the `View`→GTK renderer, and the concrete `dwl` WM backend.

## The Module contract — the central v1→v2 decision

`Module` (in core) — no GTK type appears anywhere in this trait:

```
trait Module {
    fn id(&self) -> &str;
    fn init(ctx: &ModuleContext) -> Result<Self> where Self: Sized; // wm handle, bus, cfg
    fn subscribe(&self) -> &[Topic];          // what wakes me (never busy-poll)
    fn view(&self) -> View;                   // a DESCRIPTION, not a gtk::Widget
    fn on_event(&mut self, ev: &Event) -> Dirty;   // react; Dirty=>host re-renders my subtree
    fn on_action(&mut self, a: ActionId) -> Dirty;  // a click/scroll routed back by id
    fn teardown(&mut self);                   // release WM/D-Bus/fd resources
}
```

`View` (core, **serde-serializable**) is a small node tree — enough for a panel, not a VDOM:
`Label{text,classes}`, `Icon{name|pixmap,size}`, `Row/Col{children,gap}`, `Button{child,
action:ActionId,classes}`, `Spacer`, and **`Popover{trigger:Box<View>, content:Box<View>}`** —
the popover affordance is in the contract *now* (tags/window/taskbar v1 don't use it; taskbar
hover-previews and clock's calendar will, with zero trait churn). `ActionId` is a plain
serializable id; clicks/scrolls route to `on_action` — **no GTK callback ever crosses the
boundary**.

Host side (bin): a `ViewRenderer` turns `View`→GTK, **owns the widget tree**, and wires GTK
signals → `ActionId` → `module.on_action`. On `Dirty::Yes` the host re-renders just that
module's subtree (per-module re-render is cheap; no global diff in v1).

### Module trait v1 → v2 migration notes (the highest-risk call — naming it explicitly)

- **v1**: modules are in-process, trusted; the host renders `View` directly to GTK.
- **v2** (xfce4-panel-style isolation, ref `panel/panel-plugin-external-wrapper.c`): a module
  runs in its **own process**; `View`, `Event`, `ActionId` are serialized over a socket; the
  host process renders and routes actions. **Because the trait never names a GTK type, v2 is a
  transport wrapper around the same trait, not a rewrite of every module.**
- **Rule enforced from commit one:** nothing in `Module`/`View`/`Event`/`ActionId` references
  `gtk4::*`. CI/review rejects a GTK type leaking into core. This is the single decision most
  likely to bite us, so it is a hard invariant, not a guideline.

## Event bus & main loop

One **GLib main loop** (GTK4 owns it). **`calloop` is intentionally *not* used** — adding a
second loop would fight GTK; instead we integrate every source as a GLib fd watch/timer:
`EventBus` lets modules `subscribe(&[Topic])`; sources (`Wm`, `Timer`, later `Dbus`) publish
`Event`s. The Wayland source is the dwl backend's connection fd via `glib::unix_fd_add_local`;
timers via `glib::timeout_add_local`. Subscribe, never poll (eww lesson).

## WindowManager abstraction (`src/wm/`)

`WindowManager` (core trait) is the universality seam (Cairo-Dock GLDI model, ref
`src/implementations/cairo-dock-wayland-manager.*`): `outputs()`, `tags()/workspaces()`,
`windows()`, `layout(output)`, a change subscription emitting `WmEvent`s, and commands
`focus_tag`, `set_layout`, `activate_window`, `close_window`, `set_minimized`. **Modules call
this trait, never dwl APIs.**

- **`dwl` backend** (`src/wm/dwl.rs`, bin): opens a **second, dedicated `wayland-client`
  connection** — *not* GDK's. Rationale: gtk4-layer-shell already drives the bar surface on
  GDK's connection; sharing that fd would race GTK's own dispatch. A separate connection (own
  fd, integrated via `glib::unix_fd_add_local`) is cleaner and single-threaded. It binds
  `zdwl_ipc_manager_v2` (+ `get_output` per `wl_output`) and `zwlr_foreign_toplevel_manager_v1`,
  translating dwl-ipc `tag/title/appid/layout/frame` and foreign-toplevel `title/app_id/state/
  closed` into `WmEvent`s; commands map to `set_tags`/`set_layout` and the toplevel handle's
  `activate`/`close`/`set_minimized` (ref Waybar `src/modules/wlr/taskbar.cpp`,
  `src/modules/sway/window.cpp`). Bindings are generated by **`wayland-scanner`** from the
  vendored XML — never hand-rolled.
- **Stubs** (files now, `unimplemented!()` bodies + a header comment naming the IPC each will
  speak, so the trait is validated against >1 mental model): `river.rs` (river-status +
  river-control), `hyprland.rs` (hyprland-ipc UNIX socket), `sway.rs` (sway-ipc), `i3.rs`
  (i3-ipc), `bspwm.rs` (`bspc subscribe`).

## Layer-shell, outputs, popups

Bar surface via gtk4-layer-shell, per selected output, with exclusive-zone reservation
(Plasma/Cairo-Dock discipline; X11 equivalent later = `_NET_WM_STRUT_PARTIAL` +
`_NET_WM_WINDOW_TYPE_DOCK`). Popups are GTK `Popover`s anchored to the trigger widget
(gtk4-layer-shell drives `xdg_popup` on layer surfaces). v1 modules ship none; the `View::Popover`
path exists end-to-end so M3+ adds content, not plumbing.

## Tray — full design (stubbed in `src/shell/tray/`, built in M4)

The tray earns a full subsection because its subtleties must be settled on paper, not under
M3-finish pressure. Spec: freedesktop **StatusNotifierItem** + `org.kde.StatusNotifierWatcher`
(D-Bus, via `zbus`). wafflebar is **both Watcher and Host**.

- **Watcher name-ownership race:** try to own `org.kde.StatusNotifierWatcher` with
  `DO_NOT_QUEUE | REPLACE_EXISTING`-style flags. If another Watcher already owns it, *do not
  fight* — become a Host only and watch for the existing Watcher disappearing (NameOwnerChanged)
  to take over. Two panels must coexist without flapping the name.
- **Host registration:** own `org.freedesktop.StatusNotifierHost-PID`, then call
  `RegisterStatusNotifierHost`; track `StatusNotifierItemRegistered/Unregistered` and the
  Watcher's `RegisteredStatusNotifierItems` property for cold start.
- **Item lifetime / crashes:** each item is `org.{kde,freedesktop}.StatusNotifierItem-PID-ID`;
  subscribe to `NameOwnerChanged` for each item's bus name and drop the icon the instant its
  owner vanishes (apps crash without unregistering).
- **Icon resolution:** prefer `IconName` via the freedesktop Icon Theme (our `IconTheme`,
  indigo-reality), fall back to `IconPixmap` (ARGB32 blobs, network byte order — premultiply +
  byteswap), honor `IconThemePath` overrides.
- **KDE vs Ayatana drift:** items appear under both `org.kde.*` and `org.freedesktop.*` /
  Ayatana `com.canonical.*` names; watch both. Context menus arrive via
  `com.canonical.dbusmenu` (a separate object path) **or** an `Activate` call — support both.
- **Code now:** `tray/mod.rs` = public type signatures + `// TODO(M4)` + the SNI spec URL; no bodies.

## Launcher (`src/shell/launcher/`, stubbed)

freedesktop **Desktop Entry Spec** parsing (categories, `NoDisplay`, `TryExec`), icon resolution
via GTK `IconTheme` (Icon Theme Spec), recently-used tracking. `mod.rs` = signatures + spec URL.

## Notifications (`src/shell/notifications/`, stubbed)

wafflebar *becomes* the `org.freedesktop.Notifications` daemon (zbus) + a notification-center
popover. `mod.rs` = signatures + spec URL. Only one daemon may own the name — same
not-fighting discipline as the tray Watcher.

## Dependencies

**Approved for M2** (added as reached; pause + report if any pulls a surprising heavy transitive
or a C lib needing packaging, before committing `Cargo.lock`):
`wayland-client`, `wayland-protocols` + `wayland-protocols-wlr`, `wayland-scanner` (build dep),
`gtk4-layer-shell` (already in the manifest — reused, not re-added). **`calloop`: evaluated and
*not* adopted** — GTK's GLib loop swallows our Wayland fd cleanly via `glib::unix_fd_add_local`.

**Flagged, not yet added:** `zbus` (tray + notifications, M4). **Ask-first:** `.desktop`/icon
crates, SNI/dbusmenu proxies, any GTK-ecosystem crate beyond the manifest.

## Config impact

The grid engine and TOML schema are unchanged. `build_grid` stops calling the
`build(kind)->Widget` dispatcher; instead it instantiates each `Module` via a registry, renders
its `View`, and owns the resulting widget. The M1 placeholder path is removed once tags/window/
taskbar exist (unknown module types still render a placeholder `View`, not a special code path).
